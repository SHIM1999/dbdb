PostgreSQL DB 연동 매뉴얼

프로젝트: ATMC.App.MultiRobotBolting

작성일: 2026-03-04

버전: 1.1

본 문서는 기존 SQLite + MySQL(MariaDB) 이중 저장 구조에
PostgreSQL을 세 번째 저장 대상으로 추가한 작업에 대한 설명입니다.

1. 개요

기존 시스템은 볼팅 사이클 결과를 SQLite(로컬)와 MySQL/MariaDB(서버) 두 곳에 저장하고 있었습니다.
이번 작업에서는 기존 저장 로직을 변경하지 않고, PostgreSQL을 세 번째 저장 대상으로 추가하였습니다.

사이클 완료 → SaveDB() → ① SQLite + ② MySQL + ③ PostgreSQL (신규)
세 블록은 각각 독립된 try/catch로 감싸져 있으므로, 하나가 실패해도 나머지 저장은 정상적으로 진행됩니다.

3. 설치 및 준비

3-1. PostgreSQL 서버 설치

  1. https://www.postgresql.org/download/windows/ 에서 설치 파일 다운로드
  2. 설치 시 기본 설정:
    • 포트: 5432
    • 기본 계정: postgres
    • 비밀번호: 설치 중 직접 설정 (잊지 말 것)
  3. 설치 완료 후 pgAdmin 또는 psql로 연결 확인
PostgreSQL은 MySQL과 달리 데이터베이스를 미리 생성해 두어야 합니다.
pgAdmin에서 원하는 DB명으로 Database를 먼저 생성하거나, 기본 postgres DB를 그대로 사용할 수 있습니다.
테이블(result)은 앱 시작 시 자동으로 생성됩니다.

3-2. NuGet 패키지 설치 (빌드 전 필수)

Npgsql 5.0.18은 .NET Framework 4.8 환경에서 아래 세 개의 패키지를 별도로 설치해야 합니다.
(.NET Core / .NET 5+ 에서는 런타임에 내장되어 있어 불필요하지만, .NET Framework에서는 직접 추가해야 합니다.)

패키지설치 버전필요 이유
Npgsql5.0.18PostgreSQL 드라이버 본체
System.Threading.Channels4.7.1Npgsql 내부 비동기 파이프라인 의존성
System.Text.Json5.0.2Npgsql JSON 직렬화 의존성
System.Runtime.CompilerServices.Unsafe5.0.0Npgsql 저수준 메모리 접근 의존성

설치 방법 – Package Manager Console

Visual Studio 2022 메뉴: 도구 → NuGet 패키지 관리자 → 패키지 관리자 콘솔

Install-Package Npgsql -Version 5.0.18
Install-Package System.Threading.Channels -Version 4.7.1
Install-Package System.Text.Json -Version 5.0.2
Install-Package System.Runtime.CompilerServices.Unsafe -Version 5.0.0
이미 Npgsql이 설치되어 있어도 나머지 3개 패키지를 추가로 설치해야 합니다.
packages.config 방식(.NET Framework 레거시)은 전이적 의존성을 자동으로 설치하지 않습니다.
3개 의존 패키지가 없으면 앱 시작 시 System.Threading.Channels 등의 어셈블리 로드 오류가 발생하며, PostgreSQL 연결이 실패합니다. 빌드는 성공하더라도 런타임에서 오류가 발생하므로 반드시 설치하세요.

5. 파일별 상세 설명

5-1. PostgresDB.cs

PostgreSQL 연동의 핵심 클래스입니다. 외부 의존성은 Npgsql과 표준 .NET(System.Data)뿐입니다.

메서드설명
Connect()서버에 연결하고 CreateTable()을 자동 호출
Disconnect()연결 해제 및 리소스 정리
CreateTable()result 테이블이 없으면 생성 (IF NOT EXISTS)
InsertRecord(...)결과 1건을 파라미터 바인딩으로 삽입 (@param 방식)

테이블 구조 (result)

id         SERIAL PRIMARY KEY
date       TIMESTAMP   -- 저장 시각
model      TEXT        -- 모델명
body_no    TEXT        -- 바디 번호
seq_no     TEXT        -- 시퀀스 번호
result     CHAR(2)     -- "OK" / "NG"
fit        REAL        -- 피트니스
ovl        REAL        -- 오버랩
dx/dy/dz   REAL        -- 등록 결과 위치 (mm)
drx/dry/drz REAL       -- 등록 결과 각도 (deg)
ox/oy/oz   REAL        -- 오프셋 위치
orx/ory/orz REAL       -- 오프셋 각도
result_dir TEXT        -- 결과 파일 저장 경로
컬럼 구성은 기존 SQLite DB.COL 열거형과 1:1로 일치합니다.

5-2. MySetting.cs

기존 DBServerAddress (MySQL용) 바로 아래에 5개 항목 추가:

public Property_<string> PgHost     { get; } = new Property_<string>("localhost", "DB", WriteProtectionType.AskForPermission);
public Property_<int>    PgPort     { get; } = new Property_<int>(5432,           "DB", WriteProtectionType.AskForPermission);
public Property_<string> PgDatabase { get; } = new Property_<string>("postgres",  "DB", WriteProtectionType.AskForPermission);
public Property_<string> PgUser     { get; } = new Property_<string>("postgres",  "DB", WriteProtectionType.AskForPermission);
public Property_<string> PgPassword { get; } = new Property_<string>("",          "DB", WriteProtectionType.AskForPermission);

5-3. Global.cs

DATABASE 영역에 다음이 추가되었습니다:

public static PostgresDB PgDB = null;

public static void InitPgDB() {
    try {
        PgDB = new PostgresDB(
            Setting.PgHost, Setting.PgPort,
            Setting.PgDatabase, Setting.PgUser, Setting.PgPassword);
        PgDB.Connect();   // Connect() 내부에서 CreateTable() 자동 호출
    } catch(Exception ex) { LotusAPI.Logger.Error(ex.Message); }
}

Init() 호출 순서:

InitPlc() → InitDB() → InitPgDB() → InitRobots() → InitScanners() → ...

5-4. Result.cs – SaveDB()

기존 두 블록 뒤에 세 번째 블록이 추가되었습니다. (line 132 ~ 162)

블록라인대상
try/catch #117 ~ 52SQLite (기존, 변경 없음)
try/catch #253 ~ 130MySQL/MariaDB (기존, 변경 없음)
try/catch #3132 ~ 162PostgreSQL (신규 추가 + 오류 진단 강화)
try {
    if(Global.PgDB == null) {
        Logger.Warn("PostgreSQL: PgDB is not initialized, skipping.");
    } else if(!Global.PgDB.IsConnected) {
        Logger.Error($"PostgreSQL: not connected, skipping insert. LastError={Global.PgDB.LastError}");
    } else {
        float fit = 0, ovl = 0, dx = 0, dy = 0, dz = 0, drx = 0, dry = 0, drz = 0;
        if(RegistationResult != null) {
            fit = (float)RegistationResult.Fitness;
            ovl = (float)RegistationResult.Overlap;
            var pose = new RobotPose(RegistationResult.Matrix);
            dx  = (float)pose.X;  dy  = (float)pose.Y;  dz  = (float)pose.Z;
            drx = (float)pose.Rx; dry = (float)pose.Ry; drz = (float)pose.Rz;
        }
        var pgOffset = (Model as ModelConfig).Registration.ShiftOffset;
        bool pgOk = Global.PgDB.InsertRecord(
            Model.Name, BodyNo, SeqNo, OK ? "OK" : "NG",
            fit, ovl,
            dx, dy, dz, drx, dry, drz,
            (float)pgOffset.DX,  (float)pgOffset.DY,  (float)pgOffset.DZ,
            (float)pgOffset.DRx, (float)pgOffset.DRy, (float)pgOffset.DRz,
            GetResultDir());
        if(pgOk) Logger.Log($"OK (PostgreSQL)");
        else     Logger.Error($"PostgreSQL insert failed: {Global.PgDB.LastError}");
    }
} catch(Exception ex) {
    Logger.Error(ex.Message);
    Logger.Trace(ex.StackTrace);
}
v1.0 → v1.1 변경점: 기존 코드는 InsertRecord()의 반환값(bool)을 확인하지 않아, 연결 실패 시에도 로그에 "OK (PostgreSQL)"이 표시되는 문제가 있었습니다.
변경 후에는 3단계로 상태를 분리하여 정확한 오류 원인을 로그에 기록합니다.
로그 메시지의미
OK (PostgreSQL)정상 저장 완료
PostgreSQL: PgDB is not initialized, skipping.InitPgDB() 자체가 실패 (예외 또는 설정 누락)
PostgreSQL: not connected, skipping insert. LastError=...Connect() 실패 — LastError에 원인 표시
PostgreSQL insert failed: ...연결은 됐으나 INSERT 실패

6. 런타임 동작 흐름

6-1. 앱 시작 시

Program.Main()
  └─ Global.InitGlobalSetting()   -- setting.json 로드
  └─ Global.Init()
       └─ InitDB()                -- SQLite 연결
       └─ InitPgDB()              -- PostgreSQL 연결 + 테이블 자동 생성
       └─ InitRobots() ...        -- 하드웨어 초기화

6-2. 볼팅 사이클 완료 시

Result.SaveDB()
  ├─ [try #1] DB.MyTable.InsertRow(row)          → SQLite 저장
  ├─ [try #2] MySqlConnection → INSERT             → MySQL 저장
  └─ [try #3] Global.PgDB?.InsertRecord(...)      → PostgreSQL 저장

7. 문제 해결

증상원인해결 방법
빌드 오류: Npgsql 참조 없음 NuGet 패키지 미설치 패키지 관리자 콘솔에서 4개 패키지 설치 (3-2 참조)
런타임 오류: System.Threading.Channels 어셈블리 로드 실패 Npgsql 의존 패키지 3개 미설치
(빌드는 성공해도 런타임 실패)		 패키지 관리자 콘솔에서 아래 3개 설치:
System.Threading.Channels 4.7.1
System.Text.Json 5.0.2
System.Runtime.CompilerServices.Unsafe 5.0.0
로그에 PostgreSQL: not connected
+ LastError=파일이나 어셈블리... 로드할 수 없습니다		 위와 동일 — 의존 패키지 누락으로 Connect() 내부에서 예외 발생 위와 동일
로그에 "connection refused" PostgreSQL 서버 미실행 또는 IP/포트 오류 서버 상태 확인, MySetting에서 PgHost/PgPort 재설정
로그에 "password authentication failed" PgUser/PgPassword 불일치 MySetting에서 계정 정보 수정 후 재시작
로그에 "database does not exist" PgDatabase에 지정한 DB가 없음 pgAdmin에서 해당 DB 생성 (테이블은 자동 생성됨)
로그에 PostgreSQL: PgDB is not initialized InitPgDB() 자체가 예외로 실패 앱 시작 로그에서 InitPgDB 오류 메시지 확인
로그에 PostgreSQL insert failed: ... 연결은 성공했으나 INSERT 단계에서 오류 LastError 메시지 확인 (권한 부족, 컬럼 타입 불일치 등)
PostgreSQL 저장 실패는 SQLite/MySQL 저장에 영향을 주지 않습니다.
v1.1부터 로그 메시지가 세분화되어 원인을 바로 확인할 수 있습니다.

8. 다른 프로젝트에 적용하기

이 패턴은 어느 프로젝트에도 동일하게 적용할 수 있습니다. 바꿔야 할 부분은 세 곳뿐입니다.

  1. PostgresDB.cs 복사 후 namespace를 해당 프로젝트명으로 변경
  2. CreateTable()의 컬럼 정의를 해당 프로젝트 데이터에 맞게 수정
  3. InsertRecord()의 파라미터 목록을 컬럼에 맞게 수정

연결 방식, NuGet 참조(Npgsql 5.0.18), Global/Setting 초기화 패턴은 모두 동일합니다.

Npgsql 버전 주의: 5.x는 .NET Framework 4.x 지원, 6.x 이상은 .NET 6+ 전용입니다. .NET Framework 4.8 프로젝트에는 반드시 5.0.18을 사용하세요.
